# v0.64: latent-256 VAE with overlap-transfer initialization

## Purpose

v0.64 repeats the v0.62 latent-capacity experiment, but initializes the
256-channel VAE encoder from the trained v0.2 128-channel encoder. Matching
weights are copied exactly and mismatched tensors copy their common channel
prefix; newly introduced channels keep fresh initialization. The decoder,
losses, GRL/V-REx terms, five-epoch warm-up, split, seed, and 20-epoch budget
are otherwise unchanged.

The training log reports `exact=30, partial=18, skipped=0`, confirming that the
old representation was transferred rather than silently discarded.

## Test result

Checkpoint: `best.pth`, selected by validation `total` (`1.2347`).

| Metric | Test mean |
|---|---:|
| RMSE | 0.8323 |
| MAE | 0.5352 |
| PCC | 0.3597 |
| HR error | 9.03 bpm |
| R-peak F1 | 0.9010 |
| R-peak timing error | 27.28 ms |
| QRS width error | 18.16 ms |
| RMSSD error | 56.72 ms |
| QRS amplitude ratio | 0.5583 |
| Carotid PTT error | 25.72 ms |
| Brachial PTT error | 25.69 ms |
| Parameters | 2.33M |

Compared with v0.62, overlap transfer improves RMSE (`0.8443 -> 0.8323`),
PCC (`0.2805 -> 0.3597`), HR error (`12.27 -> 9.03 bpm`), R-peak F1
(`0.8119 -> 0.9010`), peak timing (`37.96 -> 27.28 ms`), and QRS width
(`32.10 -> 18.16 ms`). It still does not beat the 128-channel v0.61 on
R-peak F1, peak timing, QRS width, or amplitude calibration. The result
supports transfer initialization as necessary for a fair wider-latent test,
but not latent-256 adoption by itself.

Figures are in
`runs/senssmarttech_v064_vae_multiband_latent256_transfer_20ep_seed42/figures/`.
