# v0.51: Frozen Reverse-Branch Cycle Experiment

## Scope

v0.51 repeats the v0.5 learned-forward-map idea with an explicit two-stage
training schedule. The ECG->PPG branch is first trained on paired observations,
then frozen before its output is used as a cycle constraint. This prevents the
two networks from jointly inventing an artificial signal family that only makes
the cycle loss small.

```text
Stage 1 (epochs 1-10)
  PPG -> main encoder -> main decoder -> ECG_hat -> L1(ECG_hat, ECG)
  ECG -> reverse encoder -> reverse decoder -> PPG_direct
                                        -> L1(PPG_direct, PPG)

Stage 2 (epochs 11-20)
  reverse encoder/decoder frozen
  PPG -> main encoder -> main decoder -> ECG_hat
                                      -> frozen reverse branch -> PPG_cycle
```

A/B activity is metadata-only and is used for post-hoc analysis. It is not an
input to either path.

- Dataset: SensSmartTech, subject-wise `22/5/5`
- Input/output: `[B, 4, 2000] -> [B, 4, 2000]`
- Seed: 42
- Epochs: 20 (10 reverse pretraining + 10 frozen-cycle)
- Config: `configs/exp_v051_frozen_reverse_cycle.yaml`
- Run: `runs/senssmarttech_v051_frozen_reverse_cycle_20ep_seed42/`
- Best checkpoint: `best.pth` (epoch 11), selected by validation `ecg_total`
- Reverse snapshot: `reverse_pretrained.pth`

## Objective

During reverse pretraining:

```text
L = L1(ECG_hat, ECG) + 1.0 * L1(PPG_direct, PPG)
```

During the frozen-cycle stage:

```text
L = L1(ECG_hat, ECG)
  + 1.0 * L1(PPG_direct, PPG)
  + 0.5 * L1(PPG_cycle, PPG)
```

VAE, Flow, GRL, IRM, QRS weighting, and STFT terms remain disabled so that the
effect of the training schedule can be isolated.

## Deployable PPG->ECG result

Metrics below are computed from the main PPG->ECG path only. The reverse branch
is not supplied as an input at inference time.

| Metric | Train | Test |
|---|---:|---:|
| RMSE | 0.8334 | 0.8454 |
| MAE | 0.4628 | 0.5278 |
| PCC | 0.4700 | 0.3060 |
| HR error (bpm) | 14.22 | 14.73 |
| R-peak F1 | 0.5761 | 0.6018 |
| QRS width error (ms) | 34.63 | 34.03 |

On the held-out test split, v0.51 improves R-peak F1 from v0.5's `0.1972` to
`0.6018` and reduces QRS width error from `67.63 ms` to `34.03 ms`. Global PCC
is similar (`0.3060` vs `0.3022`), while HR error becomes worse (`14.73` vs
`7.89 bpm`). The current result therefore supports sharper peak localization,
but not yet faithful rhythm transfer.

## Reverse and cycle diagnostics

| Split | Direct ECG->PPG L1 | Cycle PPG->ECG_hat->PPG L1 | Difference (direct - cycle) |
|---|---:|---:|---:|
| Train | 0.4671 | 0.5750 | -0.1080 |
| Test | 0.7746 | 0.5910 | 0.1836 |

The reverse branch is fixed after epoch 10. The test cycle error is lower than
the direct reverse error, but the train cycle error is higher than direct. This
means the cycle term is no longer a proof of correctness; it is a regularizer
whose benefit must be judged jointly with ECG morphology and rhythm metrics.

## Archive contents

- `eval_train.json`, `eval_test.json`: PPG->ECG waveform and physiology metrics
- `cycle_eval_train.json`, `cycle_eval_test.json`: direct/cycle reverse metrics
- `figures/`: compact A/B train/test comparison figures
- `best.pth`, `final.pth`, `reverse_pretrained.pth`, `epoch_*.pth`
- `training_history.json`: per-epoch stage and loss components

This is an experimental v0.51 checkpoint, not a final method claim. The next
controlled step should add a rhythm-aware term or QRS/HR multi-objective while
keeping the reverse branch frozen, so morphology gains can be separated from
heart-rate drift.
