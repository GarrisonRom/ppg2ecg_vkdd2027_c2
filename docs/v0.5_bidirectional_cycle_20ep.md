# v0.5: Bidirectional PPG<->ECG cycle prototype

## Scope

v0.5 tests the reverse-function idea as a learned forward physiological
constraint. It does **not** reverse convolution weights or assume that ECG and
PPG form a one-to-one mapping.

```text
PPG -> PPG encoder -> ECG decoder -> ECG_hat
ECG -> ECG encoder -> PPG decoder -> PPG_direct
PPG -> ECG_hat -> ECG encoder -> PPG_cycle
```

The direct ECG->PPG term anchors the reverse branch on paired observations. The
cycle term constrains the generated ECG to remain compatible with the learned
forward map. A/B activity is metadata-only and is not a model input.

- Dataset: SensSmartTech, subject-wise `22/5/5`
- Input/output: `[B, 4, 2000] -> [B, 4, 2000]`
- Seed: 42
- Epochs: 20
- Config: `configs/exp_v05_bidirectional_cycle.yaml`
- Run: `runs/senssmarttech_v05_bidirectional_cycle_20ep_seed42/`
- Checkpoint selection: lowest complete validation objective (epoch 7)

## Controlled objective

```text
L = L1(ECG_hat, ECG)
  + 1.0 * L1(PPG_direct, PPG)
  + 1.0 * L1(PPG_cycle, PPG)
```

VAE, Flow, GRL, IRM, QRS weighting, and STFT terms are disabled in this first
cycle isolation experiment.

## Deployable PPG->ECG result

The metrics below use only the main PPG->ECG path, as would be used at test
time. The reverse branch is not supplied as an input.

| Metric | Train | Test |
|---|---:|---:|
| RMSE | 0.9105 | 0.8373 |
| MAE | 0.5199 | 0.5221 |
| PCC | 0.3221 | 0.3022 |
| HR error (bpm) | 9.25 | 7.89 |
| R-peak F1 | 0.1771 | 0.1972 |
| QRS width error (ms) | 70.04 | 67.63 |

Compared with v0.1, global RMSE/PCC and HR error improve modestly, but R-peak
and QRS morphology become substantially worse. The compact panels still show
smoothed or mistimed complexes rather than reliable sharp QRS recovery.

## Reverse and cycle diagnostics

On the held-out test split (`cycle_eval_test.json`):

| Path | PPG L1 |
|---|---:|
| Direct ECG->PPG | 0.7617 |
| PPG->ECG_hat->PPG | 0.2172 |

The low cycle error is **not** evidence that the generated ECG is correct. The
direct reverse model is much less accurate than its cycle reconstruction, while
the ECG R-peak F1 is only `0.1972`. This pattern is diagnostic of joint-network
collusion: the PPG->ECG generator and reverse decoder can agree on an artificial
signal family that reconstructs PPG without matching the real ECG morphology.

Therefore, v0.5 is a useful negative/control result, not a successful inverse
solution. A valid follow-up must pretrain the ECG->PPG branch on direct pairs,
freeze or strongly regularize it during cycle training, and evaluate the
reverse model on held-out ECG independently.
