# v0.57 Residual High-Frequency Decoder Control

## Purpose

v0.57 tests a safer injection mechanism for the v0.56 local high-frequency
branches. Instead of replacing the D1/D2 coefficient heads, the original
v0.55-style heads remain as a base path and newly added local residual heads
are initialized to zero. The intended initial behavior is therefore the
previous broad morphology plus a learnable high-frequency correction.

## Configuration

- Dataset: SensSmartTech, subject-wise `22/5/5`
- Sampling: `250 Hz`, window length `2000`
- Seed: `42`
- Epochs: `20` (`10` ECG->PPG reverse pretraining + `10` frozen cycle)
- Config: `configs/exp_v057_residual_highfreq_decoder_wide_encoder.yaml`
- Run: `runs/senssmarttech_v057_residual_highfreq_decoder_wide_encoder_20ep_seed42/`
- Parameters: `2.96M`
- Checkpoint: `final.pth`

The exact Haar coefficient/IDWT path, loss weights, data split, and A/B
metadata policy are unchanged. Only `highfreq_residual=true` is new in the
Decoder configuration.

## Results

| Metric | v0.56 test | v0.57 test |
|---|---:|---:|
| RMSE | 0.8229 | 0.8261 |
| MAE | 0.5167 | 0.5164 |
| PCC | 0.3442 | 0.3467 |
| HR error (bpm) | 18.13 | 19.73 |
| R-peak F1 | **0.6565** | 0.4282 |
| R-peak time error (ms) | **45.57** | 67.31 |
| QRS width error (ms) | **31.12** | 61.67 |

The residual construction slightly preserves global waveform statistics, but
the additional branch does not converge sufficiently in the ten-epoch
frozen-cycle stage. This is a negative controlled result, not the new default.
The v0.56 checkpoint remains preferable when QRS localization is the primary
criterion.

For the cross-version matrix, the saved `best.pth` was also re-evaluated: RMSE
`0.8277`, PCC `0.3387`, HR error `19.66 bpm`, R-peak F1 `0.4024`, and QRS width
error `64.79 ms`. The table above preserves the original `final.pth` snapshot;
the checkpoint choice is therefore recorded explicitly in the matrix.

## Interpretation

Zero initialization protects the base path, but it also delays gradients into
the local residual stack. A useful follow-up would either train the forward
path for longer after reverse pretraining or use a small non-zero residual
initialization together with an explicit amplitude/QRS term. That follow-up
should be evaluated against v0.56, not replace it silently.
