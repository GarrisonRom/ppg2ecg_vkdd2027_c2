# v0.56 High-Frequency Decoder Branches

## Purpose

v0.56 keeps the v0.55 wide PPG Encoder and tests whether the remaining QRS
amplitude/width problem is caused by insufficient local capacity in the direct
Haar-coefficient Decoder. D1 and D2 are the finest coefficient grids, so only
those branches receive the new local residual refinement blocks and wider
coefficient heads.

## Configuration

- Dataset: SensSmartTech, subject-wise `22/5/5`
- Sampling: `250 Hz`, window length `2000`
- Seed: `42`
- Epochs: `20` (`10` ECG->PPG reverse pretraining + `10` frozen cycle)
- Config: `configs/exp_v056_highfreq_decoder_wide_encoder.yaml`
- Run: `runs/senssmarttech_v056_highfreq_decoder_wide_encoder_20ep_seed42/`
- Parameters: `2.95M`
- Main result checkpoint: `final.pth`

The Decoder still predicts `A4/D4/D3/D2/D1` coefficients and uses the fixed
orthonormal Haar IDWT as its only ECG synthesis path. The changes are:

1. D1/D2 coefficient heads use a hidden width of `64`.
2. Each D1/D2 path has two no-normalization local residual blocks with small
   dilations (`1`, `2`), so a narrow QRS excursion is not removed by
   batch-relative normalization.
3. `highfreq_gain=1.15` scales only the D1/D2 outputs.
4. 1x1 skip projections preserve the wider Encoder skip features before they
   enter the fixed-width Decoder.

The loss, PPG channels, subject split, cycle schedule, and seed are unchanged
from v0.55. A/B activity is post-hoc metadata only.

## Results

All values below use `final.pth`; the checkpoint is evaluated after the full
frozen-cycle stage rather than selecting the early reverse-pretraining
checkpoint.

| Metric | v0.55 test | v0.56 test |
|---|---:|---:|
| RMSE | 0.8206 | 0.8229 |
| MAE | 0.5096 | 0.5167 |
| PCC | 0.3535 | 0.3442 |
| HR error (bpm) | 15.89 | 18.13 |
| R-peak F1 | 0.3994 | **0.6565** |
| R-peak time error (ms) | 70.97 | **45.57** |
| QRS width error (ms) | 56.49 | **31.12** |

The architecture clearly improves peak localization and estimated QRS width,
but it does not restore the absolute amplitude of the ECG. On the test split,
the mean predicted per-lead standard deviation is only about `32%-49%` of the
target standard deviation. This explains why the global PCC/MAE do not improve
even though the local peak metrics do.

For the cross-version matrix, the saved `best.pth` was also re-evaluated: RMSE
`0.8217`, PCC `0.3403`, HR error `18.76 bpm`, R-peak F1 `0.5610`, and QRS width
error `36.01 ms`. The table above intentionally preserves the original
full-training `final.pth` snapshot; do not compare those two checkpoint choices
as if they were a method change.

## Follow-up control

v0.57 adds a zero-started additive residual head on top of the original D1/D2
heads in an attempt to preserve the broad morphology while learning extra
high-frequency detail. It restores the base path but does not learn enough
detail in the ten-epoch frozen-cycle budget; its test R-peak F1 is `0.4282` and
QRS width error is `61.67 ms`. v0.56 therefore remains the current high-
frequency checkpoint, while the amplitude bottleneck should be addressed with
explicit amplitude/QRS supervision or a longer staged schedule.
