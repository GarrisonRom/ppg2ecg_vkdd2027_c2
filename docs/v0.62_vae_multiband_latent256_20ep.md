# v0.62: VAE latent 256 + v0.52 multi-band decoder

## Purpose

This is the latent-capacity ablation of v0.61. The architecture, FFT bands,
loss weights, subject-wise split, seed, warm-up schedule, and 20-epoch budget
are unchanged. Only the temporal VAE latent is doubled from 128 channels to
256 channels (`content/style = 128/128`). Because the posterior heads change
shape, this version starts from a fresh encoder rather than partially loading
v0.2 weights.

## Test result

Checkpoint: `best.pth`, selected by validation reconstruction `total`.

| Metric | Test mean |
|---|---:|
| RMSE | 0.8443 |
| MAE | 0.5401 |
| PCC | 0.2805 |
| HR error | 12.27 bpm |
| R-peak F1 | 0.8119 |
| R-peak timing error | 37.96 ms |
| QRS width error | 32.10 ms |
| RMSSD error | 78.68 ms |
| QRS amplitude ratio | 0.3975 |
| Peak amplitude ratio | 0.3656 |
| Carotid PTT error | 43.62 ms |
| Brachial PTT error | 41.73 ms |
| Parameters | 2.33M |

Train metrics are RMSE `0.8291`, PCC `0.4779`, HR error `10.16 bpm`, R-peak F1
`0.7751`, and QRS width error `31.33 ms`.

## Interpretation

The larger latent lowers global RMSE by `0.0253` relative to v0.61, but it
substantially worsens PCC, HR transfer, R-peak F1, peak timing, QRS width, and
amplitude calibration. The generated ECG is smoother and under-amplified; the
additional channels do not automatically recover the PPG-missing QRS
information. Under the current 20-epoch schedule, latent 256 is therefore a
capacity ablation/negative result, not the new baseline.

Figures are in `runs/senssmarttech_v062_vae_multiband_latent256_20ep_seed42/figures/`.
