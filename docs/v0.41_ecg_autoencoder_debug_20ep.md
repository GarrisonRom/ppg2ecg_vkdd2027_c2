# v0.41: ECG autoencoder capacity diagnostic

## Purpose

v0.41 is the first one-factor debug experiment after v0.4. It bypasses PPG,
VAE sampling, latent Flow, GRL, IRM, and activity labels. The input and target
are the same preprocessed ECG window:

```text
ECG [4, 2000] -> baseline temporal encoder -> latent + high-resolution skips
               -> baseline ECG decoder -> ECG [4, 2000]
```

The objective is global L1. Dropout, KL, Flow, and auxiliary alignment terms
are disabled. This answers whether the target data and the existing
high-resolution encoder/decoder can reconstruct QRS complexes at all.

- Dataset: SensSmartTech, `subjectwise_per-lead`
- Split: subject-wise 22/5/5
- Seed: 42
- Epochs: 20
- Config: `configs/exp_v041_ecg_autoencoder_skip.yaml`
- Run: `runs/senssmarttech_v041_ecg_autoencoder_skip_20ep_seed42/`

## Results

| Metric | Train | Test |
|---|---:|---:|
| RMSE | 0.0663 | 0.1501 |
| MAE | 0.0366 | 0.0860 |
| PCC | 0.9971 | 0.9832 |
| HR error (bpm) | 1.12 | 1.63 |
| R-peak F1 | 0.9840 | 0.9879 |
| QRS width error (ms) | 1.39 | 3.76 |

The train detail figure shows that sharp QRS complexes are reconstructed rather
than replaced by a smooth average. Therefore:

1. The cached ECG target has not been globally flattened by preprocessing.
2. The baseline temporal Decoder has enough capacity when high-resolution skip
   features are available.
3. The v0.4 failure is not primarily a train/test generalization problem.
4. The next suspects are the v0.4 latent-only temporal bottleneck, PPG/ECG
   cross-modal information loss, and Flow/MSE amplitude shrinkage.

The ECG autoencoder is a diagnostic control, not a valid PPG→ECG result: ECG is
provided as the input and the activity labels remain unused.

## Data and implementation checks

The materialized cache was checked before interpreting the reconstruction:

- Subject-wise split is disjoint: train has 22 subjects, validation 5, and test
  5 (`22/5/5`).
- The cached PPG range is `[-10, 10]`, matching the documented PPG-only robust
  clipping. The cached ECG is not clipped: the observed ranges are about
  `[-21.1, 25.2]` in train, `[-14.9, 22.8]` in validation, and `[-9.6, 13.1]`
  in test.
- ECG normalization is per-lead mean/std estimated from train windows; it is
  not a joint PPG+ECG normalization. Therefore the missing QRS in v0.4 cannot
  be attributed to a shared normalization step flattening the ECG target.
- A forward/backward smoke check confirms the encoder output has latent shape
  `[B, 128, 125]` and skip shapes `[B, 32, 1000]`, `[B, 64, 500]`, and
  `[B, 128, 250]`, with finite decoder output and gradients.

## Sampling-rate maintenance fix

`read_csv_signal` previously converted timestamps to seconds and then applied
the unit scale a second time when reporting `fs`, producing values such as
500000 Hz for a 500 Hz source. The reported rate is now computed as
`1 / median(diff(t_seconds))`. Existing materialized caches were not changed by
this metadata-only fix; the preprocessing pipeline still resamples to 250 Hz
as configured.

## Next diagnostic

Run an ECG autoencoder with the same latent-only path used by v0.4, but without
PPG/ECG cross-modal alignment or Flow. If that path also smooths QRS while the
skip version succeeds, the temporal bottleneck is confirmed before changing the
PPG encoder or loss.
