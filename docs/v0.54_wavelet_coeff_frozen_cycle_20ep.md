# v0.54 Direct Wavelet-Coefficient Decoder

## Purpose

v0.54 tests the stronger architectural form of the wavelet idea: the PPG
path predicts ECG wavelet coefficients directly, and a fixed inverse Haar
transform (IDWT) is the only synthesis path to the ECG waveform. This is
different from v0.53, where a normal time-domain decoder was only supervised
with a wavelet loss.

## Configuration

- Dataset: SensSmartTech, subject-wise `22/5/5`
- Sampling: `250 Hz`, window length `2000`
- Seed: `42`
- Epochs: `20` (`10` ECG->PPG reverse pretraining + `10` frozen cycle)
- Config: `configs/exp_v054_wavelet_coeff_frozen_cycle.yaml`
- Run: `runs/senssmarttech_v054_wavelet_coeff_frozen_cycle_20ep_seed42/`
- Parameters: `1.452M`
- Checkpoints: `best.pth`, `final.pth`, `reverse_pretrained.pth`, and
  `epoch_{5,10,15,20}.pth`

## Model

The coefficient decoder predicts five coefficient fields:

```text
A4: [B, 4, 125]
D4: [B, 4, 125]
D3: [B, 4, 250]
D2: [B, 4, 500]
D1: [B, 4, 1000]
```

The fixed orthonormal Haar IDWT reconstructs `[B, 4, 2000]`. The transform
was checked independently: decomposition followed by reconstruction has a
maximum absolute error of approximately `4.8e-7` on a random CUDA batch.

The objective is:

```text
L = 1.00 * L1
  + 0.05 * L_derivative
  + 0.20 * L_Haar-coeff
  + 0.15 * L_Haar-QRS-envelope
  + 0.10 * L_peak-interval
```

The QRS envelope first interpolates each selected detail level (`D2-D4`) to
the original time grid, then compares normalized squared detail energy. The
peak term uses target-only envelope anchors and a differentiable local soft
argmax within an 80 ms search radius. No ECG target, R-peak mask, activity
label, or other metadata is supplied to the model at inference time.

## Results

| Metric | Train | Test |
|---|---:|---:|
| RMSE | 0.8599 | 0.8196 |
| MAE | 0.4611 | 0.5078 |
| PCC | 0.4150 | 0.3482 |
| HR error (bpm) | 13.41 | 9.27 |
| R-peak F1 | 0.2691 | 0.2199 |
| QRS width error (ms) | 51.31 | 54.75 |

Compared with v0.53, v0.54 improves the test RMSE but substantially degrades
R-peak F1 and QRS-width accuracy. The direct coefficient heads and IDWT are
therefore functioning numerically, but the current coefficient weighting and
PPG-to-ECG information bottleneck still favor broad low-frequency morphology
over sharply timed QRS complexes. This is a negative controlled result, not
evidence that wavelet decoding is already the preferred model.

## Component diagnosis

The fixed-batch diagnostic `scripts/diagnose_v054_components.py` separates
capacity from cross-modal information:

| Input to the same encoder/decoder | Haar loss before | Haar loss after 150 steps |
|---|---:|---:|
| Real ECG (target-side control) | 1.092 | 0.196 |
| PPG (cross-modal control) | 1.144 | 0.568 |

With real ECG input, D2-D4 coefficient standard deviations recover to roughly
90% of the target values. With PPG input they recover only to roughly
70%-80% on the same batch. This rules out an IDWT implementation failure and
points to the PPG encoder/cross-modal mapping as the primary bottleneck, with
the decoder's D1/D2 high-resolution branches still needing more capacity.

## Cycle diagnostics

On the test split, direct ECG->PPG L1 is `0.7739`, while the frozen cycle
PPG->ECG_hat->PPG L1 is `0.4178`. The cycle remains an auxiliary constraint;
the deployable path is PPG->ECG and A/B activity is used only for post-hoc
stratification.

## Visual outputs

Compact train/test A/B comparisons are saved under:

```text
runs/senssmarttech_v054_wavelet_coeff_frozen_cycle_20ep_seed42/figures/
```

In the detail plots, the generated signal follows the baseline and broad
periodic morphology, but true sharp QRS excursions are frequently lower,
wider, or phase-shifted. This matches the physiology metrics above.

## Next experiment

Do not increase the wavelet loss weight blindly. The next controlled test
should first compare coefficient targets and generated coefficients by level,
then use a high-resolution local coefficient head or a target-side alignment
mechanism to address missing/shifted QRS information while retaining the
current exact IDWT path.
